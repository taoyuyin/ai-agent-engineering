# Docs

`docs/` 保存跨章节、需要长期维护的教材级文档。章节正文回答一个具体主题，`docs/` 负责全书路线、写作约束和跨章节索引。

## 当前文档

| 文档 | 用途 | 更新时机 |
| --- | --- | --- |
| [roadmap.md](roadmap.md) | 54 章学习路线、工程里程碑和交付标准 | 章节范围或工程主线变化时 |
| [writing-guidelines.md](writing-guidelines.md) | 文体、引用、代码和版本规范 | 写作规范变化时 |

## 内容边界

适合放在这里：术语表、统一 Contract、版本策略、实验方法、引用清单和跨章节架构决策。

不适合放在这里：

- 单章原理和代码说明，应放在 `chapters/chapterXX/`；
- 可运行完整案例，应放在 `examples/`；
- Runtime 实现细节，应放在 `framework/`；
- 图示源文件和部署拓扑，应放在 `architecture/`。

## 文档完成标准

新增文档至少说明：目标读者、解决的问题、与章节/源码的关系、当前状态、验证方式、版本和引用。引用优先使用官方文档、协议规范和论文，不用无来源的产品宣传代替技术判断。

仓库导航从根目录 [README](../README.md) 开始，章节顺序以 [roadmap](roadmap.md) 为准。
